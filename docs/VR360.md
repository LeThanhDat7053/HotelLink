# VR360 — Đặt tour 3DVista vào dự án

Tài liệu này trả lời câu hỏi thực tế: **"bộ VR360 bỏ vào đâu, deploy thế nào"**.
Phần lý thuyết sâu (parser, resolver, race condition) nằm ở hai playbook ở thư mục gốc — xem mục 6.

---

## 1. Tour VR360 nằm ở đâu trong dự án

Bộ export 3DVista **không nằm trong `public/`** và **không nằm trong git** (thư mục `dist/` đã bị gitignore). Nó sống ở:

```
dist/
└── assets/
    ├── vr-data/          ← nguyên bộ export 3DVista
    │   ├── index.htm
    │   ├── locale/en.txt          ← parser đọc file này để lấy danh sách scene
    │   ├── script_general.js      ← và file này
    │   ├── lib/
    │   ├── skin/
    │   └── media/
    └── js/
        └── panorama.js   ← runtime 3DVista, KHÔNG được xoá khi build
```

Đây là lý do 3 thứ sau được cấu hình đặc biệt — đừng "tối ưu" chúng đi:

| Nơi | Cấu hình | Vì sao |
|-----|----------|--------|
| `vite.config.ts` | `build.emptyOutDir = false` | để build không xoá mất `vr-data` |
| `scripts/cleanup-dist-js.js` | giữ lại `panorama.js` | file này không do Vite sinh ra |
| `vite.config.ts` | plugin serve `/assets/vr-data` và `/assets/js/panorama.js` | để dev server đọc được từ `dist/` |
| `server/.htaccess` | rule bỏ qua rewrite cho `^/assets/vr-data/` và `^/assets/js/` | để Apache không trả app shell HTML thay vì file `.txt`/`.js` |

## 2. Thêm tour cho một dự án mới

1. Xin bộ export 3DVista từ bên dựng tour (một thư mục, thường vài trăm MB).
2. Copy **nguyên bộ, không tách lẻ file** vào `dist/assets/vr-data/`.
3. Copy `panorama.js` của **chính bộ export đó** vào `dist/assets/js/panorama.js`.
4. Chạy `npm run dev`, mở http://localhost:5173/assets/vr-data/locale/en.txt — phải ra **text**. Nếu ra HTML thì đường dẫn sai.
5. Chạy `npm run build` — `vr-data` phải còn nguyên sau khi build.

Quy tắc bất di bất dịch: **một bộ export duy nhất**. Không trộn `panorama.js` của export này với `vr-data` của export khác — đây là nguyên nhân phổ biến nhất của lỗi "parse được scene nhưng viewer trắng".

## 3. Trang `/vr360-scene-sync`: góc nhìn theo menu + đồng bộ scene

### 3.1 Chỉnh góc nhìn cho từng vị trí menu

Trang `/vr360-scene-sync` là công cụ cho người quản trị nội dung:

1. **Cột trái — vị trí menu:** Trang chủ, Giới thiệu, Phòng nghỉ (+ từng phòng), Ẩm thực (+ từng nhà hàng), Tiện ích, Dịch vụ, Ưu đãi, Chính sách, Liên hệ, Thư viện ảnh, Nội quy. Dòng phụ là cảnh đang gắn; nhãn **đã lưu** = vị trí có cấu hình riêng.
2. **Giữa — xem trước:** iframe `vr360-angle-picker.html` (tour thật). Kéo để xoay, lăn chuột để zoom. Dưới khung hiện `yaw · pitch · hfov` theo thời gian thực.
3. **Cột phải — cảnh:** bấm để **đổi cảnh** cho vị trí đang chọn.
4. Bấm **Lưu góc** → ghi vào `data/vr360-views.json` trên hosting. Website áp ngay ở lần tải trang kế tiếp (tab website đang mở trong cùng trình duyệt nhận luôn).

Lưu cần mật khẩu `VR360_EDITOR_PASSWORD` trong `config.php` (dev: `VR360_EDITOR_PASSWORD` trong `.env`, không đặt thì là `dev`). Chỉ xem trước thì không cần.

**Khoá lưu = đường dẫn trang** (không tiền tố ngôn ngữ, chữ thường), vd `/`, `/phong-nghi`, `/phong-nghi/dlx-dbl3`. Vì vậy hai trang dùng chung một cảnh (Trang chủ và Thư viện ảnh) có góc **riêng**, lưu trang này không đổi trang kia.

```json
{
  "version": 1,
  "updatedAt": "2026-09-29T15:55:21+07:00",
  "views": {
    "/phong-nghi/dlx-dbl3": {
      "label": "PHÒNG NGHỈ › Deluxe Triple",
      "sceneId": "panorama_EE1B…", "sceneName": "coralhotelvt_5",
      "yaw": 15.48, "pitch": -6.35, "hfov": 110,
      "updatedAt": "…"
    }
  }
}
```

Thứ tự ưu tiên khi website mở một trang:

| Cảnh | Góc |
|---|---|
| 1. `?scene=` trên link share | 1. `data/vr360-views.json` của đúng trang (nếu cảnh khớp) |
| 2. `data/vr360-views.json` của trang | 2. `yaw/pitch` của cảnh từ API backend |
| 3. `target_id` từ backend | 3. góc gốc của tour |

**Backend sập vẫn chạy:** website đọc file tĩnh `/data/vr360-views.json` trên chính hosting khách sạn, không qua `travel.link360.vn`; danh sách cảnh lấy từ bộ export khi API không trả. `hfov` được lưu để tham khảo, website chưa áp (zoom mặc định khác nhau giữa desktop/mobile).

| File | Vai trò |
|---|---|
| `server/vr360-views.php` | ghi JSON (mật khẩu, khoá file, ghi nguyên tử, giữ `vr360-views.backup.json`) |
| `src/services/vr360ViewStore.ts`, `src/hooks/useVr360Views.ts` | đọc/ghi + kho dùng chung cho App và trang chỉnh |
| `src/pages/VR360SceneSyncPage.tsx`, `src/components/vr360SceneSync/*` | giao diện trang chỉnh |
| `src/App.tsx` (`pageView`) | áp cảnh + góc theo đường dẫn đang mở |
| `vite.config.ts` (`vr360ViewsDevApi`) | giả lập PHP khi `npm run dev`, dữ liệu ở `.dev-data/` |

### 3.3 Chia sẻ OG (Facebook / Zalo / Messenger…)

Khi dán link một trang lên mạng xã hội, ô xem trước hiện **tiêu đề, mô tả, ảnh của chính trang đó**. Crawler không chạy JavaScript nên thẻ OG được `index.php` chèn **phía server** (`server/_og.php`).

**Link chia sẻ ngắn** — mỗi vị trí menu có link riêng, **tự theo domain đang chạy**:

```
https://<domain>/canh/<url_slug>      (tiền tố đổi được: SHORTLINK_PREFIX trong config.php)
```

- Dán link lên Facebook/Zalo → preview là **ảnh chụp từ góc mở trang** + tiêu đề/mô tả của trang đó.
- Mở link → website vào đúng trang, **đúng cảnh + đúng góc trong ảnh** (giữ `?utm…`).
- **Góc của link độc lập với góc của menu**: vd menu Liên hệ ở góc 1, link `/canh/lien-he` ở góc 2 → vào Liên hệ từ menu vẫn góc 1, mở link thì góc 2. Chụp lại góc 3 + Lưu → link cũ (cùng slug) mở góc 3; góc menu không đổi. Link chưa có ảnh chụp → mở ở góc của menu.
- Đổi `url_slug` → link cũ **301** sang link mới (giữ query); link cũ của trang khác không cho dùng lại. Xoá cấu hình → link đã chia sẻ vẫn mở được trang (OG mặc định). Link không tồn tại → 404.
- Nút **Chia sẻ** trên website dùng link ngắn của trang đang xem (khi khách chưa đi sang cảnh khác).

**Trên trang `/vr360-scene-sync`**: chọn vị trí menu → tab **Chia sẻ OG** ở cột phải:

- **Link chia sẻ**: tự sinh từ tên trang (✨), sửa được, Copy / mở thử; báo ngay nếu trùng.
- **Góc của link = góc của ảnh**: chụp xong bấm **Lưu** → góc chụp lưu vào `imagePose` của link (`data/share-og.json`), **không** đụng góc menu (`data/vr360-views.json`). Tab hiện góc link đang dùng + nút *Xem góc của link*.

- Preview card như bài đăng (ảnh 1.91:1, tên miền, tiêu đề, mô tả); chuyển **Tiếng Việt / English**.
- Ô nhập để trống = theo mặc định (placeholder hiện giá trị đang hiệu lực). EN trống → dùng bản VI.
- **Chụp từ góc hiện tại**: khung vàng 1200:630 hiện trên khung xem trước; ảnh được dựng lại từ tile của bản xuất (`src/utils/panoShot.ts`, WebGL) nên sạch, không dính logo/hotspot, đúng 1200×630.
- **Tải ảnh lên**: JPG/PNG ≤ 3MB (nên 1200×630).
- **Lưu OG** → `data/share-og.json`; **🗑** → về mặc định. Ảnh nằm ở `share-images/` (tên có timestamp → crawler không dính cache ảnh cũ).
- Nút **Facebook** mở Sharing Debugger cho trang đó (dùng sau khi deploy để "Scrape Again").

Thứ tự hợp nhất (field có giá trị ở lớp sau thắng):

| Lớp | Trang chủ `/` | Trang mục (`/phong-nghi`…) | Trang chi tiết (`/phong-nghi/<code>`…) |
|---|---|---|---|
| 1. Mặc định | SEO của site | `"<tên mục> – APP_NAME"`, mô tả site | `"<tên phòng…> – APP_NAME"`, mô tả ngắn (~200 ký tự), ảnh đại diện |
| 2. Tuỳ chỉnh admin | `data/share-og.json` | ← | ← |

Ảnh khi không có ảnh nào: `DEFAULT_OG_IMAGE` trong `config.php`, trống thì ảnh SEO/logo trên backend. `/en/...` (và ngôn ngữ khác tiếng Việt) dùng bản EN. Link có tiền tố sale (`/coraltest/...`) vẫn có `canonical` không kèm tiền tố. Dữ liệu phòng/nhà hàng lấy từ API được cache 10 phút ở `cache/`.

| File | Vai trò |
|---|---|
| `server/_og.php` | resolve OG + dựng khối meta + chèn vào `<!-- OG_META_START -->…<!-- OG_META_END -->` của `index.html` (xoá thẻ thừa → chỉ còn **một** bộ OG) |
| `server/share-og.php`, `server/share-image.php` | lưu OG / nhận ảnh upload (mật khẩu `VR360_EDITOR_PASSWORD`) |
| `server/_json_store.php` | ghi JSON an toàn dùng chung (cả `vr360-views.php`) |
| `src/components/vr360SceneSync/ShareOgPanel.tsx` | giao diện tab Chia sẻ OG |
| `src/utils/shareOgDefaults.ts` | mặc định để xem trước — **giữ khớp** `og_defaults()` trong `_og.php` |

Kiểm tra sau deploy:

```bash
curl -s -A facebookexternalhit https://domain.com/phong-nghi/<code> | grep -E 'og:|<title'
```

Phải thấy **đúng một** `og:title`, `og:image` là URL tuyệt đối `https://…`. Rồi dán link vào [Facebook Sharing Debugger](https://developers.facebook.com/tools/debug/) → *Scrape Again*.

### 3.2 Đồng bộ danh sách scene lên backend

Khối **"Đồng bộ danh sách cảnh lên backend"** cuối trang giữ chức năng cũ: đọc scene thật từ bộ export, preview danh sách, dựng payload rồi `POST` lên backend. Cần biến môi trường:

```env
VITE_VR360_SCENE_SYNC_ENDPOINT=<endpoint backend cung cấp>
VITE_PANORAMA_URL_DOMAIN=https://domain-khach-san.com
```

Quy trình: mở trang → bấm đọc scene → kiểm tra danh sách đủ `id`, `name`, `panorama_url` → bấm sync.

Sau khi sync, backend gán `target_id` cho từng page/section trong admin; frontend map `target_id → scene.name` rồi gọi runtime 3DVista mở cảnh.

## 4. Deploy phần VR360

`assets/vr-data/` rất nặng nên:

- **Lần đầu**: upload cả `vr-data` lên `public_html/assets/vr-data/`. Nếu File Manager timeout, nén riêng `vr-data` thành 1 zip và extract trên server.
- **Các lần sau**: loại `vr-data` khỏi gói deploy, giữ nguyên bản trên server (xem [DEPLOY_DIRECTADMIN.md](DEPLOY_DIRECTADMIN.md#5-deploy-lại-lần-2-trở-đi)).

Kiểm tra sau deploy: `https://domain.com/assets/vr-data/locale/en.txt` trả về text, không phải HTML.

## 5. Không dùng VR360 thì sao

Dự án vẫn chạy bình thường khi không có `vr-data`: website kiểm tra `assets/vr-data/index.htm`, không thấy thì mỗi trang tự dùng nền dự phòng từ backend — tour online `vr360_link` (vd `https://web-<khach-san>.vt360.vn/…`) hoặc ảnh/video — không kẹt ở màn loading (xử lý bằng `onAvailabilityChange` trong `ThreeDVistaBackground`). Không cần gỡ code. Nếu muốn ẩn hẳn trang helper, bỏ route `VR360_SCENE_SYNC` trong `src/constants/routes.ts`.
